# 36주 홈트 감량 플랜

로잉머신 · 푸시업 바 · 턱걸이 바 · 맨몸 운동으로 진행하는 36주(2026.10.19 ~ 2027.06.27) 감량 플랜입니다.
빌드 과정 없이 정적 파일만으로 동작합니다 (GitHub Pages).

## 기능

- **오늘**: 날짜별 운동(세트·횟수, 운동 이름을 누르면 방법과 영상 링크)과 식단, 체중·운동 완료·축구 기록, 측정일 결과 입력
- **운동 타이머**: 세트 체크 → 휴식 카운트다운(턱걸이 2분·버티기 45초·그 외 75초), 로잉 인터벌·템포·피라미드·존2 구간 타이머 (소리·진동·화면 켜짐 유지)
- **컨디션·통증**: 컨디션 나쁨 → 회복 세션, 무릎·발목·허리·어깨 통증별 동작 대체, 같은 부위 4일 중 3일 통증 시 진료 권고
- **식단 기록**: 끼니마다 계획대로 / 건너뜀 / 다르게 먹음, 음식 목록(99개) 검색·양 선택·직접 입력, 간식 추가, 오늘 먹은 칼로리·단백질
- **실측 소모량 추정**: 식단·체중 기록 2주로 실제 하루 소모량을 역산해 목표 칼로리 자동 보정
- **홈 화면 앱**: 휴대폰 홈 화면에 추가해 앱처럼 실행, 오프라인에서도 열림, 연결되면 밀린 기록 자동 전송
- **주간표**: 1~36주차 요일별 운동, 축구한 날 ⚽ 표시
- **목표**: 96.4kg → 75.2kg 주별·월별 목표 그래프와 표, 내 주 평균 비교, 체력 측정 기록 표
- **운동법**: 로잉 자세, 턱걸이·푸시업·하체·코어 동작 설명과 유튜브 영상 검색 링크
- **식단**: 단계별 칼로리·탄단지, 요일별 메뉴, 장보기, 바꿔 먹기
- **습관**: 수면·수분·걷기·정체기·축구하는 날 규칙

## 한 주의 틀과 축구 규칙

| 일 | 월 | 화 | 수 | 목 | 금 | 토 |
|---|---|---|---|---|---|---|
| 축구 | 회복 | 근력 A | 로잉 존2 | 근력 B | 근력 C (상체·코어) | 가벼운 로잉 |

- 일요일에 **이번 주 안 감**을 누르면 그날은 긴 로잉, 다음 날 월요일은 회복 대신 로잉 인터벌.
- 주중에 **오늘 축구함**을 누르면 그날 운동은 완료 처리, 다음 날이 하체 근력·인터벌이면 회복으로 변경.
- 한 주에 주중 축구가 2회 이상이면 토요일은 휴식.
- 축구한 평일은 식단 합계에 +300kcal.

## 측정 반영 (자동 조정)

측정일(10/17, W9·W18·W27·W36 토요일)에 턱걸이·푸시업·플랭크·로잉 10분 거리·허리둘레를 입력하면 다음 측정 전까지 처방이 조정됩니다.

| 측정 | 조정 |
|---|---|
| 푸시업 | 푸시업 계열 횟수에 (측정값 ÷ 플랜 기준값) 배율 적용 |
| 플랭크 | 플랭크·사이드 플랭크·할로우 시간에 같은 방식 배율 적용 |
| 턱걸이 | 0개 네거티브 위주 / 1~4개 그대로 / 5~9개 +1회 / 10개 이상 +2회. 지난 측정보다 늘지 않으면 난도 유지 |
| 로잉 10분 | 500m 스플릿 계산 → 존2·템포·강하게 목표 스플릿 표시 |

- 배율은 0.6~1.2배로 제한합니다 (한 번에 최대 +20%).
- 비워 둔 항목은 기본 처방 그대로입니다.

**칼로리 자동 조정**: 지난 두 주의 주 평균 체중(각 주 2일 이상 기록)이 모두 목표보다 1kg 이상 높으면 −100kcal, 1.5kg 이상 낮으면 +100kcal. 설 브레이크 기간과 1~2주차는 제외.

## 식단 기록과 칼로리 보정

- **계획대로**: 그 순간의 계획 칼로리(단계·축구·보정 반영)를 그대로 기록합니다.
- **다르게 먹음**: 음식을 검색하거나 목록에서 고르고, 없으면 직접 입력합니다. 칼로리는 1인분 기준 근사치(±15~20%)입니다.
- **음식 검색** (아래 '음식 DB' 참고)
  - 앱 기본 목록 + 식약처 음식 DB(한식·외식·프랜차이즈 메뉴 약 1.6만 개)를 앱 안에서 바로 검색 — 오프라인에서도 됨
  - 결과에 없으면 **"식약처 상품 검색"** 버튼 → 햇반·라면·과자 같은 가공식품을 서버 함수로 검색 (로그인·인터넷 필요)
  - 식약처 음식·상품을 기록할 때는 이름·칼로리·단백질을 함께 저장해, 나중에 DB가 바뀌어도 지난 기록은 그대로입니다.
- **실측 소모량**: 최근 14일 중 식단 전체 기록 10일·체중 기록 6일 이상이면
  `소모량 = 평균 섭취 − 하루 체중 변화(kg) × 7,700` 으로 계산하고,
  `권장 섭취 = 소모량 − 이번 주 목표 감량분`에 맞춰 식단을 ±250kcal 범위에서 조정합니다 (최소 1,500kcal).
  1주차(수분 감소)와 설 브레이크 기간은 계산에서 뺍니다.
- 실측 추정이 안 될 때는 체중 추이 기반 보정(2주 연속 목표 +1kg↑ → 견과 빼기 등)을 씁니다.

## 기록 수정

체중과 측정 결과는 저장하면 잠기고 버튼이 **수정**으로 바뀝니다. 수정을 누르면 다시 입력할 수 있고, **취소**(또는 Esc)를 누르면 원래 값으로 돌아갑니다. 다른 날로 이동하면 다시 잠깁니다.

## 기록 저장 방식

- **Supabase 설정 + 로그인**: 기록이 내 계정에만 저장되어 휴대폰·PC 어디서든 이어집니다.
- **로그인 전 / Supabase 미설정**: 브라우저 `localStorage`(`plan36-log-v1`)에 저장. 로그인하면 서버로 합쳐집니다.
- **오프라인·서버 연결 실패 시**: 기록은 이 기기에 저장되고 미전송 목록(`plan36-dirty-v1`)에 남습니다. 연결이 돌아올 때, 앱을 다시 화면에 띄울 때, 밀린 기록이 있으면 30초마다 자동으로 올립니다. 이미 서버에 있던 날짜도 이 기기에서 고친 값이 우선합니다.
- **오프라인 실행**: 한 번이라도 온라인에서 연 뒤에는 인터넷 없이도 열립니다. 신호가 약하면 3초 뒤 저장본으로 바로 띄웁니다. Supabase 라이브러리를 못 받은 상태로 열렸으면 연결된 뒤 다시 받아 동기화합니다.
- 체중 칸을 비우고 **저장**하면 그날 체중 기록이 지워집니다.

### Supabase 설정

1. [supabase.com](https://supabase.com)에서 프로젝트 생성 (무료 플랜).
2. **SQL Editor**에서 `supabase.sql` 실행. 이미 실행했다면 `migration-soccer.sql`, `migration-metrics.sql`, `migration-condition.sql`, `migration-meals.sql`만 실행 (여러 번 실행해도 안전).
3. **Authentication → Users → Add user** 로 내 계정 생성 (`Auto Confirm User` 체크).
4. **Authentication → Sign In / Providers** 에서 `Allow new users to sign up` 끄기.
5. **Project Settings → API Keys → Legacy API Keys** 의 `anon` key와 Project URL을 `config.js`에 입력.

> `anon` key는 공개 저장소에 올라가도 괜찮습니다 (RLS로 본인 행만 접근).
> `service_role` / secret key는 절대 넣지 마세요.

## 음식 DB

### 1) 앱 내장 음식 DB (설정 필요 없음)

식약처 「통합 식품영양성분 DB」 중 **음식**(한식·외식·프랜차이즈 메뉴)만 골라 `data/foods-kr.json`으로 넣어 두었습니다.
GitHub에 같이 올리면 끝입니다. 1회 제공량 기준이라 피자 1판처럼 큰 단위는 ¼·½ 버튼으로 조절하세요.

중복 정리:
- 띄어쓰기·기호만 다른 같은 업체의 메뉴('계란덮밥' / '계란 덮밥')는 하나로 합칩니다. 단, 칼로리 차이가 크면(25% 초과이면서 40kcal 초과) 기준이 다른 데이터로 보고 둘 다 남깁니다. 1회 제공량이 함께 표시되니 그걸 보고 고르세요.
- 앱 기본 목록과 이름이 같은 식약처 일반 메뉴는 검색에서 숨깁니다. 괄호 설명은 빼고 비교하므로 '설렁탕 (밥 포함)'이 있으면 식약처 '설렁탕'은 숨겨집니다. 업체 메뉴는 그대로 보입니다. 기준은 `js/foods.js`의 `dupOfApp`입니다.
- 온라인 상품 결과도 이름·업체·제공량이 같으면 하나만 보여 줍니다.

**데이터 다시 만들기** (식약처 데이터가 갱신됐을 때):
1. [식품영양성분 데이터베이스](https://various.foodsafetykorea.go.kr/nutrient/) 또는 공공데이터포털에서 통합 식품영양성분정보 CSV 내려받기
2. `python3 tools/build_foods.py 내려받은파일.csv data/foods-kr.json`
3. `sw.js`의 `VERSION` 숫자를 하나 올리고 커밋

### 2) 식약처 상품 검색 (서버 함수, 1회 설정)

가공식품(상품)은 수십만 개라 앱에 넣지 않고, 공공데이터포털 API를 Supabase 서버 함수로 검색합니다.
**API 인증키는 서버 함수의 비밀값에만 넣습니다. `config.js`나 GitHub에는 절대 넣지 마세요.**

1. Supabase 대시보드 → **Edge Functions** → **Deploy a new function** → **Via Editor**
2. 함수 이름 `food-search` 로 만들고, 기본 코드를 지운 뒤 `supabase/functions/food-search/index.ts` 내용을 붙여넣고 **Deploy**
   - 함수 설정의 **Verify JWT** 는 켜 둔 채로 (로그인한 나만 호출 가능)
3. **Edge Functions → Secrets** (또는 Project Settings → Edge Functions) → **Add new secret**
   - Name: `MFDS_API_KEY` / Value: 공공데이터포털 마이페이지의 **일반 인증키(Decoding 또는 Encoding 아무거나)**
4. 확인: 함수 화면의 **Test** 에서 Body에 `{"q":"햇반","debug":true}` 를 넣고 실행
   - `items` 에 이름·칼로리가 나오면 성공
   - 에러나 빈 결과면 응답 전체(`sampleKeys`, `sample` 포함)를 복사해 두세요. 필드 이름이 다르면 코드만 맞추면 됩니다.

| 앱에 뜨는 문구 | 원인 |
|---|---|
| 상품 검색은 로그인해야 쓸 수 있어요 | 로그인 전 |
| 오프라인이라 상품 검색을 할 수 없어요 | 오프라인 |
| 상품 검색 서버에 연결하지 못했어요 | 함수 미배포, 비밀값 누락, 인증키 미승인(신청 직후 최대 1~2시간) |

공공데이터포털 개발계정은 하루 호출 수 제한이 있지만, 같은 검색어는 앱이 한 번만 부르므로 개인 사용에는 충분합니다.
